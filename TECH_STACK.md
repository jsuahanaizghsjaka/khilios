# Полный технический стек Khilios

Обзор всех технологий, сервисов и протоколов в проекте VPN-сервиса Khilios. Дата: август 2026.

---

## 1. Веб-сайт (khilios.net)

**Роль:** Главная точка входа, статус узлов, правовая информация. Должен работать даже когда Telegram лежит.

### Фронтенд
- **Framework:** Next.js 16.3.0 (App Router, SSR)
- **Language:** TypeScript 5
- **Runtime:** Node.js (на Vercel)
- **React:** 19.2.0

### Страницы
- `/` — главная, тарифы, описание сервиса
- `/tariffs` — подробный каталог планов подписки
- `/status` — статус всех узлов (обновляется раз в минуту)
- `/install` — инструкция по установке (каркас, будет с гифками)
- `/legal/refund` — условия возврата
- `/legal/privacy` — политика конфиденциальности
- `/legal/offer` — публичная оферта

### Данные и Конфиг
- **Каталог:** `web/lib/config.ts`
- **Что хранит:**
  - Тарифы (цены в ₽, количество устройств, периоды)
  - Ссылки на Telegram-бот и канал
  - Расписание поддержки: 09:00-11:00 и 19:00-22:00 МСК
  - Текст гарантии возврата

### Хостинг
- **Платформа:** Vercel (бесплатно или Pro)
- **Домен:** `khilios.net` (Cloudflare, DNS-only, не прокси)
- **CDN:** Vercel Edge Network
- **Статус:** Развёрнут, готов к запуску

### Переменные окружения
| Переменная | Для чего | Статус |
|---|---|---|
| `STATUS_URL` | URL для fetch status.json (на панели) | требуется для статуса |
| `NEXT_PUBLIC_BOT_URL` | Ссылка на Telegram-бота | пусто до открытия бота |
| `NEXT_PUBLIC_CHANNEL_URL` | Ссылка на Telegram-канал | есть |

### Robots & SEO
- **robots:** `noindex` — намеренно (реклама VPN в РФ запрещена с марта 2024)
- **Трафик:** из Telegram-бота и канала, не из поиска

## 2. Панель управления (basaltworks.ru)

**Роль:** Управление узлами, выдача ключей подписки, контроль пользователей, сбор статуса.

### Основной движок
- **Панель:** Remnawave (надстройка над Xray)
- **Протокол:** Xray-core (все тяжёлые вычисления)
- **Database:** PostgreSQL (пользователи, ключи, лимиты)
- **Admin UI:** Веб-интерфейс (Remnawave)

### Развёртывание
- **Сервер:** Ubuntu 22.04 / 24.04
- **Контейнеризация:** Docker + Docker Compose
- **Reverse Proxy:** Caddy (автоматический HTTPS, разделение трафика)
- **Сертификаты:** Let's Encrypt через Caddy ACME
- **Скрипт:** `infra/panel/deploy-panel.sh`
- **Время развёртывания:** ~10-15 минут на чистой машине

### Доступ
- **Административная панель:** `panel.basaltworks.ru:2202` (доступна только с вашего IP)
- **API подписки:** `sub.basaltworks.ru/api/sub` (открыта для всех)
- **Порт панели внутри:** 3000 (слушает только локально)
- **Файрвол:** открыты только HTTPS (443) и SSH (по умолчанию 22)

### Конфиг (panel.env)
```
ADMIN_HOST=panel.basaltworks.ru    # Имя административной панели
SUB_HOST=sub.basaltworks.ru        # Имя API подписки
ADMIN_IP=203.0.113.5               # Ваш IP (только он получает доступ к админке)
ACME_EMAIL=your@email.com          # Для уведомлений Let's Encrypt
SSH_PORT=2202                      # Если не 22
PANEL_DIR=/opt/remnawave           # Куда ставить
SUB_PATH=/api/sub                  # Путь для клиентов
```

### Бэкапы
- **Скрипт:** `infra/panel/backup.sh`
- **Частота:** раз в 6 часов
- **Содержит:** дамп PostgreSQL, конфиги, ключи Reality
- **Хранилище:** выгружается наружу на отдельный сервер

### Статус узлов
- **Скрипт:** `infra/panel/status-json.sh` (cron раз в 5 минут)
- **Вывод:** `status.json` (JSON с массивом узлов и их состояниями)
- **Автопроверка:** ICMP ping до каждого узла из панели
- **Manual override:** файл на панели для ручной корректировки статуса

## 3. Узлы/Ноды (VPS серверы)

**Роль:** Проксирование трафика пользователей, маскировка под реальный сайт.

### Инфраструктура узлов

#### Текущий парк (август 2026)
| Имя | Хостер | Регион | CPU | RAM | Диск | Роль |
|---|---|---|---|---|---|---|
| `panel` / `nl-1` | mhost.ee | Нидерланды | 1 | 2 GB | 30 GB | Панель + бот + нода |
| `de-1` | mhost.ee | Германия | — | — | — | Нода |
| `se-1` | Aéza | Швеция | 1 | 4 GB | 10 GB | Нода |
| `fi-1` | Aéza | Финляндия | — | — | — | Нода |

**Правило:** Три ноды в трёх разных ASN и странах. Две ноды у одного провайдера = одна точка отказа.

### Развёртывание ноды
- **Скрипт:** `infra/node/deploy-node.sh`
- **Время:** 20 минут от чистой Ubuntu до рабочей ноды
- **Идемпотентность:** безопасно повторять
- **Требования:** Ubuntu 22.04/24.04, root-доступ

### Конфиг ноды (node.env)
```
NODE_NAME=se-1                         # Имя узла
SSL_CERT=<берётся из панели>           # Сертификат для подключения к панели
PANEL_IP=45.153.219.229                # IP панельной машины
APP_PORT=2222                          # Порт ноды (может быть разным)
SSH_PORT=22                            # SSH порт ноды
HARDEN_SSH=yes                         # Усилить безопасность SSH
VPN_TCP_PORTS="1234 4443 8443"        # SS, Reality, XHTTP
VPN_UDP_PORTS="1234"                  # Shadowsocks UDP
```

### Протоколы на ноде

#### 1. Shadowsocks, TCP+UDP 1234 (совместимый fallback)
- **Назначение:** сохранить работу уже выданных подписок во время миграции
- **Профиль:** выдаётся вместе с новыми VLESS-входами

#### 2. VLESS + Reality, TCP 4443 (основной)
- **Маскировка:** под TLS 1.3 трафик к `www.cloudflare.com`
- **Преимущество:** лучше всего против DPI
- **Профиль:** выдаётся по умолчанию в подписке
- **NL:** порт 9443, потому что 443 занят Caddy

#### 3. VLESS + XHTTP + Reality, TCP 8443 (альтернативный)
- **Транспорт:** XHTTP поверх TCP, не QUIC/UDP
- **Преимущество:** другой профиль трафика при той же REALITY-маскировке
- **NL:** порт 10443
- **Профиль:** выдаётся в той же подписке Happ

#### 4. AmneziaWG (запасной, пост-запуск)
- **Технология:** WireGuard с обфускацией рукопожатия
- **Назначение:** если обнаружат Xray целиком (1 и 2 упадут одновременно)
- **Когда добавляется:** неделя 3-4 после запуска
- **Сейчас:** отложено

### Оптимизация сети на ноде
- **Очередь пакетов:** `net.core.default_qdisc = fq`
- **Congestion control:** TCP BBR (быстрое восстановление)
- **Fast Open:** `tcp_fastopen = 3`
- **Лимиты:** 1,000,000 файловых дескрипторов

### MTProto-прокси (вспомогательно)
- **Скрипт:** `infra/node/deploy-mtproto.sh`
- **Назначение:** вход в сервис для пользователей, которые не установили основной клиент
- **Альтернатива:** если блокируют основные ноды
- **Статус:** готов, развёртывается параллельно

## 4. Telegram-бот (@khilios_vpn_bot)

**Роль:** Главная воронка продаж. Выдача пробных ключей, приём платежей, лимитирование устройств.

### Архитектура
- **Окружение:** На панельной машине в Docker
- **Скрипт:** `infra/bot/deploy-bot.sh`
- **API панели:** подключается через `http://localhost:3000` (localhost, не по сети)
- **Telegram API:** long polling, не вебхуки (не требует открывать наружу порт)
- **Database:** PostgreSQL (та же, что и панель)

### Конфиг (bot.env)
```
BOT_REPO=<URL репозитория выбранного бота>
BOT_TOKEN=<токен от @BotFather>
PANEL_API_URL=http://127.0.0.1:3000
PANEL_API_TOKEN=<токен, создаётся в панели>
ADMIN_TELEGRAM_ID=<ваш ID>
BOT_DIR=/opt/khilios-bot
BOT_BRANCH=main
```

### Функциональность
- **Пробный период:** 7 дней, без карты, без автосписания
- **Платежи:** МИР и СБП (русские платёжные системы)
- **Тарифы:**
  - Пробный: 1 устройство, 7 дней, бесплатно
  - Базовый: 2 устройства, 199 ₽/мес
  - Стандарт: 5 устройств, 299 ₽/мес (рекомендуемый)
  - Год: 5 устройств, 1990 ₽/год (166 ₽/мес)
- **Лимит устройств:** по HWID (аппаратный ID клиента)
- **Гейт:** пользователь должен подписаться на @khiliosvpn перед первой оплатой

### Выбранный бот
- **Вариант 1:** Bedolaga (готовый бот для Xray)
- **Вариант 2:** remnawave-shopbot (специально под Remnawave)
- **Вариант 3:** Собственный (если ни один не подходит)
- **Статус:** Выбор после согласования функциональности

## 7. Платёжные системы

### МИР
- **Что:** национальная платёжная система РФ
- **Интеграция:** через платёжный провайдер (например, Yandex Kassa, Robokassa)
- **Статус:** конфиг в боте

### СБП (Система быстрых платежей)
- **Что:** прямой перевод между банками (как Сбербанк P2P)
- **Интеграция:** через Yandex Kassa или аналог
- **Статус:** конфиг в боте

### Крипто
- **Статус:** **НЕ используется** (из политики "без криптовалют и зарубежных платёжных систем")

## 8. Домены и DNS

### Домены
| Домен | Регистратор | Регион | Роль | Статус |
|---|---|---|---|---|
| `khilios.net` | Cloudflare | .net | Сайт | ✅ куплен |
| `basaltworks.ru` | Timeweb | .ru | Панель + почта | ✅ куплен |

### DNS Стратегия

#### khilios.net (Cloudflare)
- **Режим:** DNS-only (серое облако), НЕ прокси
- **Хост:** Vercel (A-запись на Vercel IP)
- **Зачем DNS-only:** Vercel сам выдаёт HTTPS, прокси сломает сертификат

#### basaltworks.ru (Timeweb)
- **Режим:** DNS-only (нет прокси, не поддерживается)
- **Записи:**
  - `panel.basaltworks.ru` → A-запись на IP панели (45.153.219.229)
  - `sub.basaltworks.ru` → A-запись на IP панели (45.153.219.229)
- **TLS:** Caddy сам выдаёт через Let's Encrypt

#### Ноды
- **Записи:** НЕ регистрируются в публичном DNS
- **Почему:** IP узлов = готовая карта инфраструктуры для блокировщика
- **Адреса:** живут в конфиге подписки, который отдаёт панель

### WHOIS
- **Приватность:** включена (по умолчанию)
- **Автопродление:** включено

## 9. Безопасность и лимиты

### HWID-лимитирование
- **Что это:** ограничение одновременных устройств по аппаратному ID
- **Где:** в клиентах (Happ, Clash, и т.д.)
- **Зачем:** 5 устройств на тариф = честно 5, а не одна подписка на 40 человек
- **Реализация:** клиент отправляет HWID, панель проверяет в БД

### SSL/TLS
- **Автоматизация:** Caddy (ACME через Let's Encrypt)
- **Сертификаты:** обновляются за 30 дней до истечения
- **SNI:** используется для разделения `panel.basaltworks.ru` и `sub.basaltworks.ru`

### Firewall (ufw)
- **DE/FI/SE:** 22 (SSH), 1234 TCP+UDP, 4443 TCP, 8443 TCP
- **NL:** 2202 (SSH), 1234 TCP+UDP, 9443 TCP, 10443 TCP; 80/443 обслуживает Caddy
- **Закрыто:** всё остальное
- **На панели:** порт панели (3000) вообще не открывается наружу (только Caddy имеет доступ)

### Fail2ban
- **На что:** SSH, Caddy
- **Защита:** от brute-force атак

### SSH Hardening
- **Отключены:** PasswordAuthentication (только ключи)
- **Включены:** PubkeyAuthentication, X11Forwarding = no
- **Alive:** ClientAliveInterval = 60s

## 10. Мониторинг и логи

### Проверка узлов (status.json)
- **Откуда:** панель проверяет ноды раз в 5 минут
- **Как:** ICMP ping (echo request)
- **Для чего:** показать статус на сайте
- **Лимит:** только проверка доступности с панели (снаружи РФ), не видит блокировок

### Ручная коррекция статуса
- **Файл:** override на панели
- **Когда:** когда нода блокирована в РФ, но ICMP от панели идёт
- **Кто:** администратор вручную (нельзя автоматизировать)

### Логи
- **Где:** на каждом сервере в `/var/log/`
- **Что отслеживаем:** SSH-попытки (fail2ban), Caddy (HTTPS), Docker (панель/бот)
- **Удаление:** нет (хранятся для разбора и возможного запроса госоргана)

## 13. Технологические решения и выборы

### Почему Remnawave, а не 3X-UI?
- **Remnawave:** одна панель на несколько нод, одна подписка на всех, HWID-лимиты
- **3X-UI:** панель на каждой ноде, подписки вручную, нет HWID-лимитов
- **Для проекта:** критичны ноды-скот (20 минут развёртывания) и лимиты устройств

### Почему 3 протокола, а не 12?
- **Отпечаток:** каждый открытый порт = сигнал для DPI (Real Security тоже видит OpenVPN)
- **Детектируемость:** OpenVPN и WireGuard детектируются по рукопожатию
- **Поддержка:** 12 протоколов × 4 приложения × 3 платформы = выгорание

### Почему Reality вместо Trojan?
- **Reality:** маскировка под реальный сайт (TLS 1.3), лучше против DPI
- **Trojan:** работает, но добавляет только отпечаток, лучше нет

### Почему сайт на Vercel?
- **Блокировка витрины:** не уносит панель (разные домены)
- **Доступность Vercel из РФ:** нестабильна, проверяем перед запуском
- **Альтернатива:** свой сервер, если не открывается с мобильных сетей

### Почему Caddy, а не Nginx?
- **ACME:** Caddy встраивает Let's Encrypt, Nginx требует дополнительных инструментов
- **Routing:** просто разводит админку и подписку по разным именам
- **Автоматизм:** сертификаты обновляются сами

### Почему long polling, а не вебхуки?
- **Вебхуки:** требуют открытого HTTPS-порта на машине с базой и ключами
- **Long polling:** опрашивает сам, не требует открывать наружу ничего
- **Нагрузка:** при 15-30 клиентах неотличимы по скорости
