# bot

Telegram-бот: согласие, гейт по каналу, триал, оплата, напоминания.
Python 3.12 + aiogram 3, long polling, SQLite.

Поведение описано в [docs/bot-flow.md](../docs/bot-flow.md), что должно быть
включено и выключено — в [docs/bot-checklist.md](../docs/bot-checklist.md).
Здесь только то, что касается кода.

## Почему свой бот, а не готовый

План допускал Bedolaga или remnawave-shopbot. Отказались после того, как
собрали чеклист: весь его раздел «Выключить» — это список того, что готовые
боты делают по умолчанию.

- Рефералка с рабочей механикой и дефолтным бонусом — при рефералке,
  замороженной до ответа юриста.
- Автопродление — при обещании на сайте «автосписания нет ни на пробном,
  ни после него».
- Сбор всего подряд «на всякий случай» — при том, что каждое лишнее поле
  это ответственность при утечке и лишний ответ при запросе госоргана.

Это не настройки, а публично нарушенные обещания. Доказать, что чужой бот
не спишет деньги сам, дороже, чем написать своего: состояний шесть, экранов
десяток.

## Запуск

На панельной машине — через `infra/bot/deploy-bot.sh`, он собирает образ и
поднимает контейнер. Руками:

```bash
cp ../infra/bot/bot.env.example ../infra/bot/bot.env
nano ../infra/bot/bot.env
docker compose up -d --build
```

Локально, без Docker:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
set -a && . ../infra/bot/bot.env && set +a
DB_PATH=./local.sqlite3 .venv/bin/python -m app.main
```

## Тесты

```bash
.venv/bin/python -m pytest
```

Три из них стоят отдельного упоминания, потому что ловят то, что глазами
не находится:

- `test_prices.py` читает `web/lib/config.ts` и сверяет цены с ботом.
  Разные цифры на сайте и в боте — первая причина спора с клиентом.
- `test_gate.py` проверяет, что **сломанная проверка подписки пускает всех**.
  Это контринтуитивно, и «починить» это в обратную сторону легко.
- `test_handlers.py` проверяет, что в текстах нет запрещённого словаря
  («обход блокировок» и прочее из чеклиста).

## Что нужно сделать до первого живого пользователя

Три пункта, каждый из которых ломает сервис молча.

### 1. Сверить вызовы API панели

В `app/panel.py` пути и поля помечены `VERIFY`. Они меняются между версиями
Remnawave. Панель отдаёт свою документацию (обычно `/api/docs`) — сверить с
ней **до** первого пользователя, а не после.

Признак расхождения: панель отвечает 404 или 422, в логе бота
`PanelError`, пользователь видит «не удалось выдать ключ».

### 2. Откалибровать `TRIAL_MAX_TELEGRAM_ID`

Пока переменная пуста, отсечка по возрасту аккаунта **выключена**, и триал
выносится новыми аккаунтами за вечер: аккаунт в Telegram стоит копейки.

Значение не захардкожено намеренно. Угадать его нельзя, а ошибка в меньшую
сторону отсекает вообще всех пришедших — и обнаружится это по нулю триалов
за день, а не по ошибке в логе.

Как получить: завести свежий аккаунт (или попросить знакомого, который завёл
его на днях), узнать ID у `@userinfobot`, поставить немного ниже.

### 3. Сделать бота администратором канала

Иначе Telegram не даст проверить подписку. По правилу «сломанная проверка
пускает» бот не упадёт — гейт просто отключится, и вы узнаете об этом по
отсутствию новых подписчиков канала. `deploy-bot.sh` это проверяет на старте.

## Структура

```
app/
  main.py        точка входа, long polling, проверки на старте
  config.py      окружение, падает сразу при нехватке
  plans.py       тарифы; цены обязаны совпадать с web/lib/config.ts
  texts.py       все тексты; словарь тот же, что на сайте
  keyboards.py   клавиатуры и callback_data
  db.py          SQLite: пользователи, платежи, напоминания
  panel.py       клиент API панели  ← здесь метки VERIFY
  gate.py        проверка подписки на канал и отсечка по возрасту
  scheduler.py   напоминания за 3/1/0 дней и отключение просроченных
  handlers/
    common.py    /start, согласие, меню, инструкции, поддержка
    trial.py     гейт -> антифрод -> выдача триала
    billing.py   тарифы, инвойс, приём платежа
    admin.py     /stats, /health — только для ADMIN_TELEGRAM_ID
```

## Решения, которые выглядят как ошибки

**Сломанная проверка подписки пускает.** Проверка, отсекающая всех при
поломке, выглядит как «бот молчит», и вы теряете весь поток за то время,
пока не заметите. Пускающая — стоит нескольких неподписанных триалов.

**Платёж записывается в базу до обращения к панели.** Если панель не
ответит, факт оплаты всё равно зафиксирован. Иначе при разборе «я платил»
опереться будет не на что.

**Пользователь не удаляется из базы после истечения.** Факт выдачи триала
остаётся навсегда, иначе «дождись истечения и возьми второй» становится
инструкцией.

**Подписка не отбирается при отписке от канала.** Проверка только в момент
выдачи триала. Отбирать выданное — спор с пользователем на ровном месте.

**Оплата не проверяет подписку на канал вообще.** Платящий получает ключ
сразу. Держать оплаченный доступ в заложниках — верный способ получить
первый возврат и первый плохой отзыв в один день.

## Бэкап

База лежит в docker-томе `bot-data` и **в дамп панели не попадает**.
Заполнить `BOT_DIR` и `BOT_DB_CONTAINER` в `infra/panel/backup.sh`, иначе
при потере VPS уедут подписки и история оплат, а панель восстановится как
ни в чём не бывало — и выяснится это в момент восстановления.
