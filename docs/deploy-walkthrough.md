# Развёртывание панели: шаг за шагом

Инструкция для владельца. Все команды выполняются **на вашей машине и на
сервере**, не в этом репозитории — у автоматики нет доступа к вашим VPS.

Про устройство скрипта — комментарии в `infra/panel/deploy-panel.sh`.
Здесь только порядок действий и что проверять после каждого.

Занимает 30–40 минут в первый раз. Если что-то пошло не так — стоп, не
идите дальше: следующий шаг обычно опирается на предыдущий.

---

## Что нужно до начала

- [ ] Сервер панели: чистая Ubuntu 22.04 или 24.04, root-доступ. У вас это
      `45.153.219.229`.
- [ ] SSH-ключ на вашем ноутбуке. Проверить: `ls ~/.ssh/id_ed25519.pub`.
      Нет — создать: `ssh-keygen -t ed25519`.
- [ ] DNS уже настроен (вы это сделали в Timeweb):
      `panel.basaltworks.ru` и `sub.basaltworks.ru` → `45.153.219.229`,
      обе записи DNS-only, без проксирования.

Проверить DNS с ноутбука перед всем остальным:

```bash
dig +short panel.basaltworks.ru
dig +short sub.basaltworks.ru
```

Обе должны вернуть `45.153.219.229`. Если нет — дальше идти нельзя:
Caddy не выпустит сертификат, пока имена не резолвятся на сервер.

---

## Шаг 1. Положить ключ на сервер

С ноутбука:

```bash
ssh-copy-id root@45.153.219.229
```

Введёт пароль один раз. После этого проверьте вход по ключу:

```bash
ssh root@45.153.219.229 "echo ключ работает"
```

Должно напечатать «ключ работает», не спрашивая пароль. Если спрашивает —
ключ не лёг, разберитесь сейчас: скрипт закроет вход по паролю, и без
рабочего ключа вы потеряете доступ к серверу.

---

## Шаг 2. Забрать репозиторий на сервер

```bash
ssh root@45.153.219.229
# теперь вы на сервере
apt-get update && apt-get install -y git
git clone https://github.com/jsuahanaizghsjaka/khilios /opt/khilios
cd /opt/khilios/infra/panel
```

---

## Шаг 3. Заполнить panel.env

```bash
cp panel.env.example panel.env
nano panel.env
```

Что вписать:

| Поле | Значение | Откуда |
|---|---|---|
| `ADMIN_HOST` | `panel.basaltworks.ru` | уже стоит по умолчанию |
| `SUB_HOST` | `sub.basaltworks.ru` | уже стоит |
| `ADMIN_IP` | ваш домашний IP | узнать: на ноутбуке `curl ifconfig.me` |
| `ACME_EMAIL` | ваша почта | сюда придут письма об истечении сертификата |

Про `ADMIN_IP`: с этого адреса — и только с него — будет открываться
админка. Если у вас дома динамический IP (обычно так), не мучайтесь со
списком — оставьте заведомо чужой адрес и ходите в админку через
SSH-туннель (шаг 6). Это надёжнее и не ломается при смене адреса.

Сохранить в nano: `Ctrl+O`, `Enter`, `Ctrl+X`.

---

## Шаг 4. Запустить

```bash
./deploy-panel.sh
```

Скрипт по порядку: обновит систему, перекинет SSH на порт 2202, поднимет
файрвол, поставит Docker, запустит панель и Caddy.

**Не закрывайте эту сессию, пока не проверите новый SSH-порт** — скрипт
предупредит об этом. Откройте ВТОРОЕ окно терминала и проверьте:

```bash
ssh -p 2202 root@45.153.219.229 "echo порт 2202 работает"
```

Работает — старую сессию можно закрывать, дальше вход только через 2202.
Не работает — вернитесь в первую сессию (она ещё открыта) и разберитесь,
не выходя.

---

## Шаг 5. Проверить сертификат и подписку

Дайте Caddy минуту на выпуск сертификата, потом с ноутбука:

```bash
curl -sI https://sub.basaltworks.ru | head -n1
```

Должно вернуть `HTTP/2 200` или `301/302` — что угодно, кроме ошибки
сертификата. Если пишет про самоподписанный или недоверенный сертификат —
Caddy ещё выпускает, подождите минуту и повторите. Если через 5 минут не
прошло — смотрите логи Caddy на сервере: `journalctl -u caddy -n 50`.

---

## Шаг 6. Войти в админку через туннель

Админка наружу закрыта намеренно. Чтобы в неё попасть, с ноутбука:

```bash
ssh -p 2202 -L 8080:127.0.0.1:3000 root@45.153.219.229
```

Пока эта сессия открыта — откройте в браузере `http://127.0.0.1:8080`.
Это и есть админка панели. Первый вход попросит создать администратора —
задайте логин и длинный пароль, сохраните в менеджер паролей.

---

## Шаг 7. Создать токен API для бота

В админке: **Settings → API tokens → Create** (точный путь зависит от
версии). Права — минимально необходимые для управления пользователями.
Скопируйте токен — он понадобится боту в `PANEL_API_TOKEN`.

---

## Готово. Что дальше

Панель жива. Теперь по порядку:

1. **Ноды** — `infra/node/deploy-node.sh` на каждой нодовой VPS. `SSL_CERT`
   для них берётся в панели: **Nodes → Create**.
2. **Бот** — `infra/bot/deploy-bot.sh` на этой же панельной машине. Токен
   API из шага 7, токен бота от @BotFather. Настройка — в `bot/ADMIN.md`.
3. **Роутинг** — правила из `infra/panel/routing/` вставить в шаблон
   подписки. Как именно — в `infra/panel/routing/README.md`.
4. **Статус на сайте** — повесить `infra/panel/status-json.sh` в cron и
   отдать `status.json` наружу, прописать его адрес в `STATUS_URL` на Vercel.

---

## Смените пароль root

Если пароль сервера хоть раз проходил через переписку или чат — считайте
его скомпрометированным и смените сразу после того, как вход по ключу
подтверждён (шаг 1):

```bash
passwd
```

Вход по паролю скрипт и так отключил, но пароль root — это ещё и sudo, и
консоль хостера. Дешевле сменить, чем гадать, кто его видел.
